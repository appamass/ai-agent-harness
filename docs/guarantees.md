# Guarantees

What the harness promises, how it does it, and **which test enforces each promise**. A guarantee without a test is not
listed here. The randomized fault-injection test [`tests/test_stress.py`](../tests/test_stress.py) injects crashes, provider outages, broken hooks,
and denied approvals and checks after every step: the protocol is intact (rows 1, 2), no tool runs twice, even after a crash and recovery (row 7, one
worker), irreversible and write actions run only after approval (row 5), hooks cannot be bypassed (row 3), and completed results survive a crash (row 8).
CI runs a few hundred scenarios; `HARNESS_STRESS=3000 pytest tests/test_stress.py` runs thousands. With a database configured, one in four also runs on a real PostgreSQL.

| # | Guarantee | Mechanism | Proven by |
|---|---|---|---|
| 1 | **Every run ends with a defined status** — even on provider outages, errors in hooks, tools, context sources, or adapters, and on task cancellation | The runner catches all error paths; the intentional exceptions are listed below | `test_failures.py`, `test_runner.py`, `test_stress.py` |
| 2 | **Message history is always API-compliant** — every tool call receives exactly one result, and roles strictly alternate | `RunState` enforces the protocol on every change and verifies loaded checkpoints | `test_types_and_state.py`, `test_stress.py` |
| 3 | **Guardrails are fail-closed** — a crashing or misbehaving hook blocks execution instead of letting actions slip through | `HookPipeline` | `test_failures.py::test_crashing_hook_fails_closed`, `::test_invalid_decision_from_hook_fails_closed` |
| 4 | **No tool runs outside the execution gate** — schema validation, policy check, hooks, human approval, and timeout | `ToolExecutor` (`ai_agent_harness/tools/executor.py`) | `test_architecture.py::test_only_tool_executor_awaits_tool_run` (only the executor calls a tool), `test_tools.py::test_policy_is_checked_before_hooks` and the rest of the gate order |
| 5 | **Irreversible actions never run without human approval**: denied at `read_only` and `suggest`, approval-gated above | `PermissionPolicy` (`ai_agent_harness/policy.py`) | `test_runner.py::test_irreversible_tool_never_runs_without_approval_even_when_autonomous`, `test_stress.py` |
| 6 | **An approval or answer applies only to the request that was shown** — a stale dialog can never approve a later action | `state.pending_id`, checked by `resume` ([ADR 0014](adr/0014-bind-resume-to-pending-call.md)) | `test_resume.py::test_stale_approval_never_approves_the_next_action`, `tests/live/` |
| 7 | **No duplicate execution across parallel workers** — `resume` claims the run before any tool or model call executes | Optimistic concurrency lock (`revision`) in every `CheckpointStore` | `test_edge_cases.py::test_concurrent_resume_of_approval_never_executes_twice`, `test_sqlite_store.py`, `test_postgres_store.py` |
| 8 | **Crash-safe (write-ahead)** — state is persisted before every tool call, including results already completed in the current batch; after a crash only the genuinely interrupted tool is reported to the model as "outcome unknown" and nothing is blindly re-run | `resume(..., recover=True)` | `test_edge_cases.py`, `test_format_v2.py`, `test_stress.py` |
| 9 | **Runtime dependencies never touch checkpoints** — DB sessions, HTTP clients, and user tokens are passed via `deps=` and never serialized | `state.deps_as(Type)` ([ADR 0012](adr/0012-format-v2-and-runtime-dependencies.md)) | `test_deps.py` |
| 10 | **Failover-safe** — thinking blocks carry their `provider_id`, so foreign signatures are stripped on failover; malformed tool-call JSON goes back to the model instead of aborting the run | `without_foreign_thinking`, `ToolCall.arguments_error` | `test_format_v2.py`, `test_router.py`, `test_anthropic_provider.py` |
| 11 | **Limits cannot be bypassed** — steps, tokens, and wall-clock time apply across all resumes; oversized requests end as `limit_reached` before the provider is called; human inputs are length-bounded | `Limits` | `test_budgets_and_killswitch.py` (context and input limits), `test_resume.py::test_limits_apply_across_resumes`, `test_runner.py::test_step_limit`, `::test_token_limit` |
| 12 | **Kill switch** — stops all or specific tenants before the next model call, before any tool, and on user input, even for already approved actions | `KillSwitch` | `test_budgets_and_killswitch.py`: `test_active_kill_switch_stops_before_the_first_model_call`, `test_kill_switch_flipped_mid_run_prevents_the_tool`, `test_kill_switch_blocks_an_already_approved_action`, `test_kill_switch_also_blocks_user_input` |
| 13 | **No sensitive internals leak into the model context or errors** — internal exceptions are reported by type name only; validation errors omit raw input values; provider and database adapters never copy request bodies, keys, or connection strings into errors; `SecretGuard` blocks credentials and private keys and names only the pattern category, never the value | `ToolExecutor`, `ModelRouter`, `SecretGuard`, adapters | `test_tools.py::test_internal_tool_errors_do_not_leak_details`, `test_security_guards.py`, `test_anthropic_provider.py`, `test_postgres_store.py` |
| 14 | **Strict tenant isolation** — checkpoint keys are `(tenant_id, run_id)`, IDs are validated against path traversal, and a checkpoint stored under another key is rejected | `persistence.py`, `persistence_sqlite.py`, `persistence_postgres.py`, `restore_state` | `test_guardrails_and_persistence.py`, `test_sqlite_store.py`, `test_postgres_store.py` |
| 15 | **Events contain metadata only** — status, tool name, risk, and counters; never arguments, results, reasons, or message text, so logs can be shipped safely | `Event` ([ADR 0011](adr/0011-operational-limits-and-metadata-events.md)) | `test_failures.py::test_events_never_contain_content` |
| 16 | **Upgrades never strand waiting runs** — checkpoints carry `schema_version` and migrate on load; unknown future versions are rejected cleanly | `restore_state` ([ADR 0010](adr/0010-checkpoint-schema-versioning.md)) | `test_schema.py`, `test_format_v2.py` |
| 17 | **Compaction preserves protocol and full checkpoint history** — compacting context replaces old tool results only in the model request view with a placeholder, strictly preserving message alternating roles; checkpoints retain full conversation history | `Agent.compact_context`, `context_floor` ([ADR 0026](adr/0026-token-estimate-and-context-compaction.md)) | `test_compaction.py` |
| 18 | **Parallel tools never run write operations or bypass the gate** — concurrency applies strictly to consecutive `parallel_safe=True` read tools under `max_parallel_tools` bound; write tools and approvals run sequentially, write-ahead saves before groups, and call order is preserved | `runner._run_batch`, `ToolExecutor.parallel_safe` ([ADR 0027](adr/0027-parallel-read-tools.md)) | `test_parallel_tools.py`, `test_stress.py` |
| 19 | **Encrypted checkpoints cannot be tampered with or transposed** — AES-256-GCM authenticated metadata header (AAD) binds key ID, tenant ID, run ID, and revision; altering metadata or ciphertext fails decryption; unencrypted states fail closed | `AesGcmCodec`, `load_state` ([ADR 0029](adr/0029-checkpoint-encryption-and-retention.md)) | `test_encryption.py`, `test_sql_store_contract.py` |
| 20 | **Retention purge never touches active or waiting runs** — `purge_finished` deletes only terminal runs (`done`, `refused`, `blocked`, `limit_reached`, `failed`, `cancelled`) older than the retention window evaluated against the database clock | `SqliteCheckpointStore.purge_finished`, `PostgresCheckpointStore.purge_finished` ([ADR 0029](adr/0029-checkpoint-encryption-and-retention.md)) | `test_sql_store_contract.py::test_purge_finished_deletes_only_old_terminal_runs` |
| 21 | **Delegation never widens privileges or strands a run** — a sub-agent is a read tool whose specialist must be `read_only` and cannot offer `ask_user`; any sub-run status other than `done` comes back to the caller as a tool error, a sub-run that would wait is cancelled at once, and one a crash interrupted is closed by the recovery job (see the guide); with a checkpoint store on the specialist, the same call never starts a second sub-run; cycles (also back to the top-level agent) and chains deeper than 4 are refused | `sub_agent` ([ADR 0030](adr/0030-sub-agents-as-read-only-tools.md)) | `test_sub_agents.py` |
| 22 | **Cancelling never runs anything and answers every open call honestly** — `cancel` ends a waiting run, or with `recover=True` a crashed one, as `cancelled` without a model call, a tool, or a `before_tool` hook; finished batch results stay, other calls are answered "not executed" or, after a crash, "outcome unknown"; with a checkpoint store, the optimistic lock makes a later resume of another copy of the same revision fail | `cancel` ([ADR 0031](adr/0031-cancel-waiting-or-crashed-runs.md)) | `test_cancel.py` |

**Intentional exceptions propagated to the caller:** `ConcurrencyError` (another worker owns the run), checkpoint write failures
(failing loudly beats silent data loss), `asyncio.CancelledError` after the status `cancelled` was recorded cleanly, and `ValueError` /
`InvalidStateError` for over-long input or wrong `resume` arguments, which are raised before any run state changes.

## What these guarantees are not

- They hold for the code paths the harness controls. They do **not** make a model correct, and they do not stop prompt injection by
  themselves: real protection comes from least-privilege tools, human approval, argument validation, and egress filtering.
- Tools you write are yours: the harness decides *whether* a tool may run, not what it does once it runs. Keep write tools idempotent.
  See also [`known-limitations.md`](known-limitations.md).
